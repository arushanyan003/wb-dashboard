# Финансовый дашборд Wildberries

Автоматически забирает данные из Wildberries API (отчёт о продажах по
реализации) и показывает их в виде интерактивного веб-дашборда: выручка,
комиссии, логистика, штрафы, хранение — в динамике и в разрезе по артикулам.

## Из чего состоит проект

| Файл | Что делает |
|---|---|
| `database.py` | Схема базы данных (таблицы и подключение) |
| `collector.py` | Забирает данные из WB API и кладёт в базу |
| `scheduler.py` | Запускает `collector.py` каждый день автоматически |
| `dashboard.py` | Сам дашборд — то, что ты открываешь в браузере |

Дашборд и сборщик данных — это **два разных процесса**. Дашборд только
читает базу, сборщик — только пишет в неё. Так дашборд работает быстро и
не зависит от скорости ответа WB API.

## Деплой на Railway (пошагово)

Это самый простой вариант — без работы с серверами и Linux-командами.

### 1. Подготовка

1. Зарегистрируйся на [railway.com](https://railway.com) (можно через GitHub).
2. Залей эту папку (`wb-dashboard`) в свой репозиторий на GitHub.
   Если не пользовался GitHub — самый быстрый способ:
   - Зайди на [github.com/new](https://github.com/new), создай пустой репозиторий.
   - На странице репозитория нажми "uploading an existing file" и закинь туда
     все файлы из этой папки.

### 2. Создание проекта на Railway

1. В Railway нажми **New Project → Deploy from GitHub repo** и выбери свой репозиторий.
2. Railway найдёт `requirements.txt` и предложит Python-окружение — соглашайся.

### 3. Добавление базы данных

1. В том же проекте нажми **New → Database → Add PostgreSQL**.
2. Готово — Railway сам создаст переменную `DATABASE_URL` и подключит её
   ко всем сервисам проекта автоматически.

### 4. Настройка переменных окружения

В настройках сервиса (Variables) добавь:

```
WB_API_TOKEN=твой_токен_из_личного_кабинета_WB
HISTORY_START_DATE=2024-02-01
```

`DATABASE_URL` добавлять не нужно — Railway подставит её сам, если база
подключена к этому сервису (Settings → убедись, что Postgres добавлен в
тот же проект).

### 5. Создание двух сервисов из одного репозитория

Тебе нужны **два отдельных сервиса** на основе одного и того же кода:

**Сервис 1 — дашборд (то, что видишь в браузере)**
- Settings → Start command:
  ```
  streamlit run dashboard.py --server.port $PORT --server.address 0.0.0.0
  ```
- Settings → Networking → Generate Domain — получишь публичную ссылку.

**Сервис 2 — сборщик данных (работает в фоне, без интерфейса)**
- В проекте нажми **New → GitHub Repo** и выбери тот же репозиторий ещё раз
  (это создаст второй независимый сервис).
- Settings → Start command:
  ```
  python scheduler.py
  ```
- Не подключай к нему публичный домен — он не нужен, это фоновый процесс.
- В Variables этого сервиса добавь те же переменные (`WB_API_TOKEN`,
  `HISTORY_START_DATE`) — Railway не делится переменными между сервисами
  автоматически.

### 6. Первый запуск

После деплоя сервис `scheduler.py` сразу запустит первую синхронизацию
(возьмёт всю историю с `HISTORY_START_DATE`). Это может занять время:
WB разрешает **1 запрос в минуту**, так что если у тебя данные за
год — загрузка истории займёт от нескольких минут до пары часов в
зависимости от объёма продаж. Дальше будет догружаться только новое,
это быстро.

Зайди в Railway → сервис scheduler → Logs, чтобы видеть прогресс.

Когда в логах появится "Синхронизация завершена" — открывай ссылку
дашборда, данные уже там.

## Локальный запуск (для проверки перед деплоем)

```bash
python -m venv venv
source venv/bin/activate  # на Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# впиши свой токен в .env

python collector.py     # один раз — загрузить данные
streamlit run dashboard.py   # открыть дашборд локально
```

По умолчанию без `DATABASE_URL` используется локальный файл SQLite
(`wb_dashboard.db`) — удобно для проверки, не нужно поднимать Postgres.

## Важно знать

- **Лимит API**: WB разрешает 1 запрос в минуту на этот метод отчёта.
  Это уже учтено в коде — при большой истории первая загрузка просто
  займёт время, поторопить её нельзя.
- **Глубина истории**: данные по этому отчёту доступны не раньше
  29 января 2024 года — это ограничение самого WB API, не дашборда.
- **Изменение API в будущем**: Wildberries планирует в 2026 году
  перевести этот отчёт на новую версию метода (категория токена
  "Финансы" вместо "Статистика"). Когда это случится, нужно будет
  обновить только функцию `fetch_report_chunk()` в `collector.py` —
  остальной код менять не придётся. Подробности будут в
  [журнале изменений WB API](https://dev.wildberries.ru/en/release-notes).
- **Токен**: храни его только в Variables на Railway, никогда не
  коммить `.env` с реальным токеном в публичный репозиторий
  (файл `.env` уже добавлен в `.gitignore`, если будешь копировать —
  проверь, что он там есть).

## Расширение дашборда

Если захочешь добавить данные не только из отчёта о реализации, но и
оперативные данные (заказы, остатки на складах) — это отдельные методы
WB API (`/api/v1/supplier/orders`, `/api/v1/supplier/stocks`), их нужно
будет добавить отдельными функциями в `collector.py` и отдельными
таблицами в `database.py`.
